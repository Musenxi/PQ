# Polymarket BTC 5 分钟「延迟狙击 + 配对锁定」策略说明（纸面交易）

一份自包含的策略规格，供其他 AI / 研究者参考复现。全部结论来自纸面（模拟）交易，未下过任何真实订单。

## 1. 策略一句话

在 Polymarket 的 BTC 5 分钟涨跌市场里，用 Binance 现货的先行跳动发现 Polymarket 盘口的滞后定价，先买入被低估的一边（leg-1）；若随后对边价格跌到足够便宜，买入等量对边（leg-2），使 Up+Down 合计成本 < $1，把结算必付的 $1 锁成无风险差价。配不上对时，leg-1 裸奔到结算。

灵感来源：2026-11-15 X 上一则帖子声称有人用此法日赚约 $500（该声称未经独立验证）。实测图景与帖子叙事有重要出入，见第 6 节。

## 2. 市场与结算机制（已实测核实）

- 市场：Polymarket BTC Up/Down 5 分钟窗口，slug 为确定性格式 `btc-updown-5m-<窗口起始 unix 时间戳>`，经 Gamma API `https://gamma-api.polymarket.com/events?slug=...` 获取；`clobTokenIds[0]=Up, [1]=Down`（以 outcomes 顺序为准）。
- 结算：**Chainlink TWAP-60 秒**（市场字段 `cryptoMarketConfig: btc-5m-twap-60`），不是现货快照价。胜负判定可用 Polymarket 官方端点 `https://polymarket.com/api/crypto/crypto-price?symbol=BTC&variant=fiveminute&eventStartTime=<窗口起始>`：返回 `openPrice`（开盘基准价），窗口结束后 `completed=true` 并给出 `closePrice`；**Up 胜 iff closePrice ≥ openPrice**。
- 手续费：市场 feeSchedule 为 `crypto_fees_v2`，taker 费率 **0.07**，每腿模拟费用 `fee = shares × 0.07 × p × (1−p)`。

## 3. 数据源与轮询

- Binance 现货 BTCUSDT（主站 api.binance.com 在我们的运行环境被地区封锁，改用官方镜像 `data-api.binance.vision`），约每 2 秒轮询，作为先行信号。
- Polymarket CLOB `https://clob.polymarket.com/book?token_id=...` 取 Up/Down 两边的最优买卖价与量。
- Chainlink 开盘基准价取自上节 crypto-price 端点的 openPrice。

## 4. 公允价模型

```
P(Up) = Φ( ln(S_est / S_open) / (σ × √τ_eff) )
```

- `S_open`：窗口的 Chainlink 开盘基准价。
- `S_est`：当前 Binance 现货，减去窗口开盘时测得的 Binance−Chainlink 基差（basis 校正）。
- `σ`：由最近约 120 秒 Binance 收益序列估的每秒波动率（样本不足时回退 0.00012）。
- `τ_eff = max(剩余秒数, 15)`：下限 15 秒是对 TWAP-60s 结算平滑尾段的近似。
- P(Down) = 1 − P(Up)。

## 5. 交易规则

**Leg-1（方向性入场）**，全部条件同时满足才买，每窗口最多一笔，固定仓位 **$6**（shares = 6 / ask）：

1. 模型公允价 − 该边卖价 ≥ **0.08**；
2. Binance 近 **20 秒**涨跌幅 ≥ **$20**，且方向与买入边一致（买 Up 需上跳，买 Down 需下跳）；
3. 卖价 ∈ **[0.15, 0.92]**；
4. 最优卖价挂单量 ≥ 所需 shares；
5. 窗口剩余时间 ≥ **60 秒**。

**Leg-2（配对）**：持有单边期间，若 `leg1_price + 对边卖价 + 对边单位费用 < 0.95` 且对边挂单量 ≥ 持有 shares 的 90%，买入与 leg-1 **等量**的对边。配对完成后盈亏锁定：`PnL = shares − 两腿总成本 − 两腿总费用`，与结算方向无关。

**仓位管理**：无止损、无提前退出，持有到结算。未配对仓位 PnL =（买对边时）shares − 成本 − 费用，或（买错边时）−成本 − 费用。

**结算记账**：`PnL = 获胜边 shares − Σ(成本+费用)`。

## 7. 核心发现

1. **真正的 edge 在配对锁定**：两边卖价 + 费用 < $1 时利润即锁定，迄今全部兑现。利润规模取决于错位程度：配对成本越低、leg-1 价格越低（同额买到越多份数），单笔利润越大——极端错位时一笔可达 +$31.51，远超常态的 +$0.4 ~ +$2.2。
2. **配对成败由行情形态决定**：震荡市里现货在开盘价上下穿梭，触发入场的跳动很快回落，对边卖价在入场后数秒至数十秒内跌到 0.26–0.34，配对迅速完成；单边趋势市里对边只会越来越贵，leg-1 必然裸奔。
3. **方向性 leg-1 本身不产生可靠利润**：入场信号是「刚跳完 20 秒」，买点在局部极值附近；5 分钟 BTC 窗口均值回归多于趋势延续，TWAP-60s 结算又平滑尾段。未配对且方向做错时亏损 ≈ 全额本金 + 费用（约 −$6.2/笔）。
4. **盈亏平衡算术**：常态配对单笔盈利（约 +$0.4 ~ +$2.2）需要 3–9 笔才能抵 1 笔未配对亏损；但极端错位窗口的一笔大配对（+$31.51）可以抵约 5 笔。策略期望主要由「配对率 × 错位程度分布」决定。
5. **与原帖叙事的出入**：原帖把结算简化为现货价、把 leg-1 描述成近乎无风险的狙击；实测中 TWAP 结算 + 均值回归使 leg-1 成为主要风险源，利润几乎全部来自配对环节。

## 8. 工程要点

- 采集进程由带自动重启的服务托管（systemd，Restart=always），保证 24 小时连续运行。
- 记账不依赖内存状态：进程启动时扫描交易日志，把「已交易未结算」的窗口逐个用官方端点补结算，保证统计完整。
- 结算查询非阻塞：窗口结束后 closePrice 约需 60–90 秒才发布（completed=true），等待结算不能阻塞新窗口的轮询。

## 9. 已知局限

- 纸面成交假设按最优卖价全额成交、无滑点、无延迟；真实环境中这本质上是延迟竞赛，实盘成交质量必然更差。
- 样本仍小（当前运行仅 8 个交易窗口），配对全胜不应外推；+$31.51 的极端配对是低频事件。
- 费率、市场规则可能变化；σ 估计与 TWAP 近似都较粗糙。
