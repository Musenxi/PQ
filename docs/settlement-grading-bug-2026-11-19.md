# 结算判卷口径错误 — 发现、修正与影响（2026-11-19）

## 一句话

此前全部账本（影子农场、1h 探针、实盘探针，历史上还有狙击三线）用
polymarket.com 的 crypto-price 端点 `closePrice >= openPrice` 判定每个窗口的赢家；
但 BTC up/down 市场实际按 **Chainlink TWAP** 结算、按 **Gamma 官方结果
（outcomePrices，UMA resolved）** 赔付。两个口径在农场 run2 的 227 个窗口中有
**27 个不一致**。FAIR 此前的纸面盈利有很大一部分是这个判卷假象：等于用生成信号的
同源价格（现价打印）给自己判卷。

## 发现过程

- 2026-11-19 19:30 JST 窗口（`btc-updown-5m-1795084200`）：实盘探针买 Up 成交，
  机器人按 crypto-price 汇报「Up 赢 +$1.43」；lizi 在 Polymarket App 里看到的是输。
- 核查：该窗 crypto-price 为 open 63755.296 → close 63761.164（+5.87，按端点口径 Up 赢），
  但 Gamma `outcomePrices = ["0","1"]`，官方结算 **Down** 赢，CLOB 实际赔付 Down。
  钱包 data-api 的 REDEEM 记录数（6 条）与修正后胜场数（6）吻合，现金流逐分对账闭合。
- 机制：市场按最后 60 秒 TWAP 结算；crypto-price 的 closePrice 行为接近边界时刻的
  单点价格。近乎平局的窗里，均价与末点价可以落在开盘价两侧。不一致样本中多数
  |close−open| < $40，最极端一例达 $79.9（`btc-updown-5m-1795020000`，
  端点口径 Up，官方 Down）。

## 修正

1. **代码**：`farm.py`（现行 v2.0.1）、`farm_v2_1.py`、`farm1h.py`、`live_probe.py` 的
   `settlement()` 全部改为只认 Gamma：市场 `closed` 且 `outcomePrices` 决定性
   （max ≥ 0.999、和 ≤ 1.001）且 `umaResolutionStatus == "resolved"` 才记账；
   crypto-price 仅保留记录 open/close。0.5/0.5 分拆结算回退旧口径。
   注意：`outcomePrices` 在 UMA 提案期是临时值，必须等 `resolved`——修正过程中
   观察到个别窗口的 Gamma 报价在数十分钟内翻转过。
2. **账本**：`fix_settlements_gamma.py` 对农场与 1h 探针的 `settlements.jsonl` 做全量
   事后修正：对每个判反窗口，按 (账户, 窗口) 从 `trades.jsonl` 汇总双边股数，
   Δpayout = 真赢家股数 − 原记赢家股数，pnl 与 cash_after 链、state.json 的
   cash/pnl/wins 同步平移（成本与费用不变）。原文件备份为 `.bak-gammafix`。
   修正后逐窗复核：228 个 5m 窗 + 7 个 1h 窗与 Gamma **零不一致**；
   state.json 各账户 pnl 与修正后账本逐户对齐。
3. **实盘探针**：错误行（1795084200）已改记为 Down、pnl +1.4265 → −3.5735 并标注
   `corrected`；机器人已向 lizi 发送更正消息。
