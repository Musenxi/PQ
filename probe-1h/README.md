# BTC 1h FAIR 探针（纸面）

部署：2026-11-19 ~11:24 JST，VPS 服务 `paper-farm1h.service`（目录 `/root/polymarket-farm1h`），代码 `farm1h.py`（farm.py v2.0.1 的移植：同一执行模型、同一盘口新鲜度记录——每笔成交带 `book_age_ms` / `book_hash` / `would_reject`）。

## 为什么开这条线

Polymarket 2026-11-17 公告、2026-11-20 23:59 UTC（= 11-21 08:59 JST）生效的费率调整：BTC 5/15 分钟市场 taker feeRate 0.07 → 0.05，**其余加密市场 0.07 → 0.01**。5 分钟线的结论（统计零）经测算不被 0.05 翻案；但 1 小时市场费用拖累降至 1/7，三道结构性障碍（费用、定价速度、链路摩擦）中第一道基本拆除，第二道在 1 小时尺度上未测过——这是本探针存在的理由。

## 市场机制（2026-11-19 核对）

- 标的：`btc-updown-1h-<整点 unix>`；结算源为 Chainlink BTC/USD **TWAP-60** 数据流，最终值 ≥ 初始值判 Up（与 5 分钟同一族结算）。
- 结算数据：`crypto-price` API `variant=hourly` 的 openPrice/closePrice；已对过去小时与 Gamma outcomePrices + CLOB winner 交叉验证一致。该 API 的链连续性亦吻合（上一小时 close ≈ 下一小时 open）。
- 盘口（部署时抽样）：liquidityClob ≈ $5.9k、24h 成交量 ≈ $1k——**薄**。结论只适用于每窗约 $5–60 的规模，不外推。
- 费率：逐窗实时读 feeSchedule；部署时为 0.07，2026-11-21 08:59 JST 起 0.01。

## 设计

- 单家族 FAIR × 12 配置：gap {0.03, 0.06, 0.10} × tau_min {300, 900}（剩余秒数下限，在 1h 尺度上两者都真实绑定，配置互不相同）× band {(0.15, 0.92), (0.30, 0.80)}。每户 $50 纸面本金、$5 注金。
- 开盘后 60 秒内不开仓（ENTRY_DELAY_S=60）；basis 只取开盘前样本、最多平均前 8 个窗口；公允价沿用 TWAP 感知形式（结算两端同为 TWAP-60 读数）。
- 成交模型与农场 v2 相同：决策 tick 排队、下一 tick 按 VWAP 走深度成交（≥99% 深度）、记录 `wait_s` / `attempts`。

## 预注册判读标准（2026-11-19 部署时定稿，先于任何结果）

1. 记账单位 family × window，用 `farm_report.py`：per-window 均值、block bootstrap 95% CI、Bonferroni CI、先行 1h 走势（事前）regime 分层。**只看家族层面，单个配置只作描述，不许挑配置。**
2. 新鲜度归因用 `fair_booksplit.py`（与 5m 农场同一工具、同一 1000ms 主阈值）：判读同时看三个数——fresh 组 CI、fresh − stale 每窗均值差、500/2000ms 阈值下结论是否与 1000ms 一致。
3. 正式判读门槛：**降费生效后 ≥100 个已结算窗口且 ≥5 天**（降费前的数据只作管道验证、单独报告——费率差 7 倍，混在一起读没有意义）。~3 天时可出一次明确标注的冒烟读数，不作结论。
4. 判定：正式读数 CI 不含 0 且为正 → 探针通过第一关，下一步讨论（仍不直接谈实盘）；CI 含 0 或为负 → 与狙击线同标准：无证据，关停或降级为观察。先验明确记录在案：大概率仍是零，本探针的价值在于成本结构真的变了、且测试成本近乎为零。
5. 已知混杂，先行声明：(a) 运行横跨降费时点，靠逐窗实读费率处理，判读按第 3 条拆分；(b) 薄盘口下报价存活/撤单动态与 5m 不同，`would_reject` 归因照常适用；(c) 任何重启后 basis 需等下一个整点才有样本（保守设计，重启后第一个小时 FAIR 不开仓）。
